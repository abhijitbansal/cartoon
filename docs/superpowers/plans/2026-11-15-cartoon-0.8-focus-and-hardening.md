Measured 2026-11-15 on Claude Code 2.1.325 (headless `claude -p`, scratch project): with `permissions.deny` or `permissions.ask` = `Bash(make deploy:*)`, `make deploy` is blocked without the hook and **runs** with the hook (rules are evaluated against the rewritten `cartoon --merge-streams -c '…'` string and the hook returns `allow`).

**Interfaces:**
- Produces:
  - `pub struct UserRules { pub guards: Vec<String> }` — raw `ask`+`deny` rule strings for the Bash tool (`"Bash"`, `"Bash(<pattern>)"`), plus `pub unreadable: bool` (a settings file existed but failed to parse).
  - `pub fn load_user_rules(cwd: &Path, home: Option<&Path>) -> UserRules` — reads, in this order, `$CLAUDE_CONFIG_DIR/settings.json` or `<home>/.claude/settings.json`; `.claude/settings.json` and `.claude/settings.local.json` in `cwd` and every ancestor of `cwd`; managed settings (`/Library/Application Support/ClaudeCode/managed-settings.json` on macOS, `/etc/claude-code/managed-settings.json` on Linux). Collects `permissions.ask` and `permissions.deny` entries whose tool is `Bash`.
  - `pub fn is_guarded(cmd: &str, rules: &UserRules) -> bool`
  - `rewrite_decision_in(input, deny, wrap_scripts, fallback, rules: &UserRules)` in `mod.rs` gains the `rules` parameter; the existing public wrappers (`rewrite_decision`, `rewrite_decision_with_scripts`) pass `&UserRules::default()`.

Matching rules for `is_guarded` (conservative: when unsure, guarded):
- `rules.unreadable` → true.
- `"Bash"` or `"Bash(*)"` → true.
- `"Bash(<p>:*)"` → prefix match of `<p>`; `"Bash(<p>)"` containing `*` → glob, `*` = any run of characters; otherwise exact match. Whitespace runs normalised to one space before comparing.
- Candidates compared: the full trimmed command, each `&&` segment (trimmed), and each segment with leading `NAME=value` words removed.
- Any other rule shape for Bash (unknown syntax) → true.

### Task 5: Hook coverage for real agent shapes

**Files:**
- Create: `src/hook/shapes.rs` — pre-lex normalisation of a raw command into `Shape { cd: Option<String>, body: String, filter: Option<String> }`.
- Modify: `src/hook/mod.rs` (`wrap_command_in` ~782).
- Test: unit tests in `src/hook/shapes.rs` and `src/hook/mod.rs`; `tests/e2e_hook.rs`.

**Interfaces:**
- Consumes: `crate::cli::DISPLAY_FILTERS` (Task 4), `crate::adapters::find_adapter`.
- Produces: `pub(super) fn normalise(cmd: &str, root: Option<&Path>) -> Option<Shape>`.

Rules:
- **Trailing `2>&1`:** a final token exactly `2>&1` on the last segment (before any pipe) is stripped (merge-streams already merges). Any other redirection still means no rewrite.
- **One trailing pipe** to `head`/`tail` with only `-n N`, `-nN`, `-N`, `--lines=N` (N digits), or to `xcbeautify`/`xcpretty` with no args or only `--quiet`, `-q`, `--is-ci`, `--disable-colored-output`, `-s`, `--simple`, `--no-color`: accepted only when the left side is a single segment whose argv has an adapter (`find_adapter`). The rewrite keeps the filter inside the `-c` string so `cartoon -c` drops and discloses it: `cartoon --merge-streams -c 'xcodebuild test -scheme App | tail -40'`.
- **Leading `cd <dir> &&`:** `<dir>` relative, no `..`, not starting with `-`, unquoted, and `canonicalize(root.join(dir))` exists and starts with `canonicalize(root)`. Rewrite: `cd <dir> && cartoon --merge-streams -c '<rest>'`. Paths in `<rest>` are still judged against `root`.
- **Self-wrap check:** replace `trimmed.contains("cartoon")` with "the command word of any segment has basename `cartoon`".
